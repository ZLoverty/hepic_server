# v1.1.x

## v1.1.1

- fix: zeroable flag is not marked in test mode

## v1.1.0

- Rewrote the zero/tare logic: the server now sends a signal to make the loadcell tare itself instead of subtracting a local offset, so force readings stay synchronized across different terminals.
- Added zero support to the rotary encoder sensor.
- Sensors now report whether they are zeroable via a dynamically computed flag instead of a static `zeroable` field in the config; removed the now-redundant `zeroable`/`label` entries from `sensors_config.yaml`.
- `test_mode` is now compatible with the client zero command.
- Fixed shutdown logic that could block on exit.
- Server now detects IP address changes.
- `OSError` is now logged as a warning instead of an error.
- Fixed a `writer.drain()` stuck issue on disconnect, and added a reconnect test to cover it.
- Assigned a fallback value to `zero_address`, since it's effectively constant for Arizon TW20A devices.
- New install script that no longer requires global sudo; installs as a systemd service reading its config from `/etc/hepic_server`.
- Added a GitHub Actions workflow to automate releases.
- Updated README to reflect the new installation process.
